# 📘 C++11 for Competitive Programming – Comprehensive Notes

# 1️⃣ The `auto` Keyword (Type Inference)

## 🔹 What It Is

`auto` tells the compiler:

> “You figure out the type at compile time.”

It does **not** make C++ dynamically typed. Type is still known at compile time.

---

## 🔹 Why It Matters in Contests

In competitive programming, you frequently use:

- `map<string, pair<int,int>>`
    
- `vector<vector<pair<int,int>>>`
    
- iterators with long template names
    

Typing full types wastes time and makes code harder to read.

---

## 🔹 Example

### Without `auto`

```cpp
map<string, pair<int,int>>::iterator it = m.begin();
```

### With `auto`

```cpp
auto it = m.begin();
```

Much cleaner. If you later change the map type, this line still works.

---

## 🔹 When to Use `auto`

✅ Iterators  
✅ Long template types  
✅ Return values from STL functions  
⚠️ Avoid when type clarity is important (e.g., integer overflow cases)

---

## 🔹 Key Insight for Exams

`auto` improves:

- Maintainability
    
- Readability
    
- Speed of coding
    

There is **zero runtime penalty** because type is resolved at compile time.

# 2️⃣ Initializer Lists `{}`

## 🔹 What They Are

C++11 allows initializing containers using brace syntax:

```cpp
vector<int> v = {1,2,3};
```

Instead of:

```cpp
vector<int> v;
v.push_back(1);
v.push_back(2);
v.push_back(3);
```

---

## 🔹 Why This Is Powerful

In contests, you often need:

- Quick test vectors
    
- Predefined mappings
    
- Grid directions arrays
    
- Constant lookup maps
    

---

## 🔹 Example: Map Initialization

```cpp
map<int,string> numeral = {
    {0, "zero"},
    {1, "one"},
    {2, "two"}
};
```

Cleaner and safer.

---

## 🔹 Contest Use Case

Define direction vectors:

```cpp
vector<pair<int,int>> directions = {
    {1,0}, {-1,0}, {0,1}, {0,-1}
};
```

Very common in grid BFS/DFS problems.

# 3️⃣ Range-Based For Loops

## 🔹 What It Is

Replaces iterator-based loops.

### Old Way

```cpp
for (auto it = v.begin(); it != v.end(); ++it)
    cout << *it;
```

### C++11 Way

```cpp
for (auto x : v)
    cout << x;
```

---

## 🔹 How It Works

`for (auto x : container)` means:

> For each element in container, copy it into x.

---

## 🔹 Modifying Elements

To modify original elements, use reference:

```cpp
for (auto& x : v)
    x *= 2;
```

Without `&`, you modify a copy.

---

## 🔹 Contest Advantages

- Cleaner graph traversal:
    

```cpp
for (auto v : G[u])
    if (v != parent)
        dfs(v);
```

- Cleaner frequency iteration
    
- Cleaner adjacency traversal
    

---

## 🔹 When NOT to Use

Avoid when:

- You need index (`i`)
    
- You need parallel iteration
    

---

# 4️⃣ Custom Ranges (Python-style loops)

The article shows how to implement:

```cpp
for (auto i : range(10))
```

This mimics Python’s:

```python
for i in range(10):
```

---

## 🔹 Why This Is Interesting

It demonstrates:

- STL iterator flexibility
    
- How range-based for loops work internally
    
- Zero-cost abstraction (compiler optimizes away)
    

---

## 🔹 Practical Reality

In real contests:

👉 Most programmers still use:

```cpp
for (int i = 0; i < n; i++)
```

Custom range classes are elegant but rarely necessary.

# 5️⃣ Lambda Functions

## 🔹 What They Are

Anonymous functions defined inline.

General form:

```cpp
[capture](parameters) -> return_type {
    body
}
```

---

## 🔹 The Capture Clause `[&]`

This is VERY important.

- `[&]` → capture all visible variables by reference
    
- `[=]` → capture by value
    
- `[x]` → capture only x
    

---

## 🔹 Why Lambdas Are Powerful in Contests

Before C++11:

- You needed global variables
    
- Or functor classes
    
- Or static comparator functions
    

Now:

You can access local variables easily.

---

## 🔹 Example: Custom Sort

```cpp
sort(order.begin(), order.end(),
    [&](int a, int b) {
        return heights[a] < heights[b];
    }
);
```

### Why This Is Powerful

The lambda accesses `heights` without needing it global.

---

## 🔹 Typical Contest Uses

✅ Custom sorting  
✅ Priority queues with custom comparator  
✅ Binary search condition  
✅ STL algorithms (`for_each`, `count_if`, etc.)

---

## 🔹 Important Warning

Avoid recursive lambdas in contests — they are awkward and error-prone.

---

# 6️⃣ `std::array`

## 🔹 What It Is

Fixed-size array integrated with STL.

```cpp
array<int, 10> arr;
```

Unlike:

```cpp
int arr[10];
```

---

## 🔹 Advantages

- Has `.size()`
    
- Works with STL algorithms
    
- Safer
    
- Supports `.begin()` and `.end()`
    

---

## 🔹 Contest Use Case

Useful when:

- Fixed small size
    
- Need STL compatibility
    

But many competitive programmers still use raw arrays for simplicity.

---

# 7️⃣ Move Semantics (VERY IMPORTANT)

## 🔹 The Problem in Old C++

Returning large objects caused expensive copies:

```cpp
vector<int> f() {
    vector<int> v;
    return v;  // deep copy (before C++11)
}
```

---

## 🔹 What Move Semantics Does

Instead of copying:

- It transfers internal pointer ownership
    
- Does NOT copy entire data
    

Think of it like:

> “Steal the data instead of duplicating it.”

---

## 🔹 Why This Matters in Contests

Now you can safely:

- Return vectors
    
- Return strings
    
- Return maps
    
- Pass by value in some cases
    

Without worrying about performance.

---

## 🔹 Performance Insight

Move semantics makes C++ more competitive with languages like Java in terms of return-by-value efficiency.

2. Improves abstraction without performance loss

4. Reduces boilerplate
    

---

# ⚖️ When NOT to Overuse C++11

In contests:

- Overengineering wastes time
    
- Fancy abstractions may increase debugging time
    
- Simpler is often safer
    

Best practice:

> Use C++11 to simplify code — not to show off language features.

---

# 🧠 Key Concept: Zero-Cost Abstraction

Many C++11 features (auto, lambdas, range-for) do NOT add runtime overhead.

They improve:

- Expressiveness
    
- Safety
    
- Development speed
    

Without sacrificing:

- Performance
    

This is central to modern C++ philosophy.
