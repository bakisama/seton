# 📘 C++17 for Competitive Programming — Deep Notes

C++17 is a **major quality-of-life upgrade** for competitive programmers.

While C++11 introduced the revolution,  
C++17 introduced **cleaner syntax, safer behavior, and powerful STL upgrades**.

Many competitive programmers consider:

> C++17 = The most practical CP standard.

---

# 🔥 1️⃣ Structured Bindings (MOST IMPORTANT FEATURE)

## 🔹 What It Is

Allows unpacking objects directly.

### Before (C++11):

```cpp
auto p = make_pair(3, 5);
int x = p.first;
int y = p.second;
```

Or:

```cpp
int x, y;
tie(x, y) = p;
```

---

### C++17:

```cpp
auto [x, y] = p;
```

---

## 🔥 Why This Is Game-Changing

Structured bindings make:

- Dijkstra cleaner
    
- Map iteration readable
    
- Graph algorithms clearer
    
- Priority queue unpacking easy
    

---

## 🔹 Example: Iterating Map

```cpp
for (auto [key, value] : m)
    cout << key << " " << value;
```

No `.first`, `.second`.

---

## 🔹 Dijkstra Example (Huge Readability Boost)

```cpp
while (!q.empty()) {
    auto [dist, u] = *q.begin();
    q.erase(q.begin());

    for (auto& [w, v] : g[u]) {
        ...
    }
}
```

This is MUCH cleaner than nested `.first`, `.second`.

---

## 🎯 Contest Impact

Structured bindings reduce:

- Typing
    
- Logical mistakes
    
- Code complexity
    

This is arguably the **most useful C++17 feature for CP**.

# 🔥 2️⃣ Fold Expressions

## 🔹 Problem Before C++17

Variadic templates required recursion:

```cpp
template<typename T, typename... Args>
T sum(T a, Args... args) {
    return a + sum(args...);
}
```

---

## 🔹 C++17 Fold Expression

```cpp
template<typename... Args>
auto sum(Args... args) {
    return (args + ...);
}
```

This expands to:

```
((a + b) + c) + d
```

---

## 🔹 Practical CP Use

### Reading multiple inputs:

```cpp
template<typename... Args>
void read(Args&... args) {
    ((cin >> args), ...);
}
```

### Printing multiple values:

```cpp
template<typename... Args>
void print(Args... args) {
    ((cout << args << " "), ...);
}
```

---

## 🧠 Why Useful?

- Cleaner utility functions
    
- Powerful debug tools
    
- Cleaner CP templates

# 🔥 3️⃣ `if` and `switch` with Initializer

Very practical.

---

## 🔹 Example

```cpp
if (auto [it, inserted] = s.insert(42); inserted) {
    ...
}
```

Variable exists only inside the `if`.

---

## 🔹 Why Important

Cleaner scope management.

Used heavily with:

- `map.insert`
    
- `insert_or_assign`
    
- `find`
    

---

# 🔥 4️⃣ Class Template Argument Deduction (CTAD)

Before:

```cpp
pair<int,int> p = {1,2};
```

Now:

```cpp
pair p = {1,2};
```

Compiler deduces types.

---

## 🎯 Contest Benefit

Less typing, cleaner code.

Especially useful for:

- `pair`
    
- `tuple`
    
- custom structs
    

---

# 🔥 5️⃣ `std::optional`

Represents:

> “Value may or may not exist.”

---

## 🔹 Example

```cpp
optional<int> findPath(...);
```

Instead of:

- Returning -1
    
- Using special values
    
- Using boolean flags
    

---

## 🔹 Use

```cpp
if (auto dist = findPath(...); dist)
    cout << *dist;
```

Or:

```cpp
cout << findPath(...).value_or(-1);
```

---

## 🎯 CP Use?

Moderate.

Helpful when:

- Clean API design
    
- Avoiding magic values
    

But not commonly used in tight contest code.

---

# 🔥 6️⃣ `std::gcd` and `std::lcm`

Instead of:

```cpp
__gcd(a, b)
```

Now standard:

```cpp
gcd(a, b);
lcm(a, b);
```

Cleaner and portable.

---

# 🔥 7️⃣ `std::clamp`

```cpp
clamp(x, low, high);
```

Equivalent to:

```cpp
max(low, min(x, high));
```

Useful in:

- Geometry
    
- Bounding values
    
- Binary search corrections
    

---

# 🔥 8️⃣ Map Improvements

## 🔹 `insert_or_assign`

Before:

```cpp
if (m.count(k))
    m[k] = val;
else
    m.insert({k,val});
```

Now:

```cpp
auto [it, inserted] = m.insert_or_assign(k, val);
```

Clean and fast.

---

## 🔹 `extract()` — Change Key!

Normally, map keys are immutable.

Now:

```cpp
auto node = m.extract(2);
node.key() = 42;
m.insert(move(node));
```

Only way to modify key without reallocation.

---

## 🔹 `merge()`

Move elements between maps:

```cpp
m1.merge(m2);
```

Useful when merging structures efficiently.

---

# 🔥 9️⃣ Evaluation Order Rules (Important!)

C++17 defines stricter evaluation order.

For example:

```cpp
a << b << c;
```

Now guaranteed:

- `a` evaluated first
    
- then `b`
    
- then `c`
    

Before C++17 → Undefined behavior possible.

---

## 🎯 Why This Matters

Prevents subtle bugs.

Example:

```cpp
cout << f() << g();
```

Now evaluation order predictable.

---

# 🔥 🔟 `emplace_back` Returns Reference

```cpp
auto& r = v.emplace_back(10);
r = 42;
```

Avoids extra indexing.

---

# 🔥 1️⃣1️⃣ Free Functions: `size()`, `empty()`, `data()`

Instead of:

```cpp
v.size()
```

You can write:

```cpp
size(v)
```

Works for arrays too.

Makes generic programming easier.

---

# 🔥 1️⃣2️⃣ Non-const `string::data()`

You can modify string buffer:

```cpp
char* p = str.data();
p[0] = 'H';
```

Mostly useful for C-API interaction.

---

# 🔥 1️⃣3️⃣ `[[fallthrough]]`

Prevents warning in switch:

```cpp
case 2:
    [[fallthrough]];
case 3:
```

Cleaner and explicit.

---

# 🔥 1️⃣4️⃣ `*this` Capture in Lambdas

C++17 simplifies:

```cpp
[*this]
```

Instead of:

```cpp
[self = *this]
```

Not commonly used in CP.
