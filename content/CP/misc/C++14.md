# 📘 C++14 for Competitive Programming – Deep Notes

C++14 is often described as a “minor” update to C++11.

From a **competitive programming (CP)** perspective, that’s mostly true.

👉 The revolution happened in C++11.  
👉 C++14 refines and simplifies some of those features.

But some improvements are **very useful in contests**.

---

# 🔥 What Actually Matters for Competitive Programming?

Most important features still come from **C++11**:

- Range-based for loops
    
- Lambdas
    
- `auto`
    
- Brace initialization
    
- `unordered_map` / `unordered_set`
    
- Move semantics
    
- `tuple`, `tie`
    
- Variadic templates
    

C++14 adds improvements that make these even smoother.

---

# 1️⃣ Numeric Literals (Digit Separators + Binary Literals)

## 🔹 Digit Separator `'`

You can now separate digits using `'` for readability.

```cpp
auto num = 10'000'000;   // 10^7
```

This improves clarity in:

- Large constraints
    
- Mod values
    
- Bit masks
    
- Time limits
    

---

### Floating-Point Example

```cpp
auto fnum = 0.000'015'3;  // 1.53e-5
```

---

### Spacing Doesn't Matter

```cpp
auto snum = 1'0'0'000'00;  // still 10000000
```

It’s purely for readability.

---

## 🔹 Binary Literals (`0b`)

Now officially supported:

```cpp
auto bnum = 0b0100'1100'0110;
```

Very useful for:

- Bitmask DP
    
- Subset problems
    
- Debugging binary states
    

---

## 🎯 Competitive Advantage

Binary literals reduce errors when dealing with:

- Masks like `(1<<k)`
    
- Predefined bit patterns
    
- State compression DP
    

---

# 2️⃣ `std::gets` Removed

Removed because it causes:

- Buffer overflow
    
- Runtime errors
    

In contests, always use:

```cpp
getline(cin, s);
```

or

```cpp
fgets()
```

This is more about safety than new power.

---

# 3️⃣ Generic Lambdas (Very Important)

## 🔹 C++11

You had to specify types:

```cpp
auto f = [](int x, int y) { return x + y; };
```

---

## 🔹 C++14

You can use `auto` in parameters:

```cpp
auto f = [](auto x, auto y) { return x + y; };
```

The compiler deduces types automatically.

---

## 🔥 Why This Is Powerful

Allows:

- Truly generic comparator functions
    
- Cleaner templates
    
- Type-independent utilities
    

---

## 🔹 Practical Contest Example

```cpp
auto cmp = [](auto a, auto b) {
    return a.second < b.second;
};
```

Works for:

- `pair<int,int>`
    
- `pair<long,long>`
    
- Custom structs (if compatible)
    

---

## 🧠 Conceptual Insight

Generic lambdas are syntactic sugar for:

> A templated function object

This makes lambda functions much closer to real generic tools.

---

# 4️⃣ Improved `std::tuple` and `std::get`

## 🔹 C++11

Access by index only:

```cpp
get<2>(t);
```

---

## 🔹 C++14

You can access by type:

```cpp
get<string>(t);
```

---

## ⚠️ Important Limitation

If tuple contains two elements of the same type:

```cpp
tuple<int, string, int>
```

Then:

```cpp
get<int>(t);  // ❌ ambiguous
```

Compilation error.

---

## 🎯 Contest Use?

Rare.

Most competitive programmers still use:

```cpp
get<0>(t)
```

Or better:

```cpp
tie(a,b,c) = t;
```

---

# 5️⃣ Rvalue References (Performance Boost)

This was introduced in C++11 but emphasized in the blog.

## 🔹 What It Means

You can pass temporary objects by reference:

```cpp
string mul(string&& a, string&& b);
mul("10", "30");
```

Before C++11:

- Temporary objects couldn’t bind to non-const references.
    

---

## 🔹 Why It Matters in CP

Move semantics + rvalue references:

- Avoid deep copies
    
- Make big integer operations faster
    
- Speed up heavy string/vector operations
    

Example from blog:

> Big integer multiplication sped up 30–40%

---

## 🧠 Conceptual Understanding

Rvalue references allow:

- Move constructors
    
- Move assignment operators
    
- Efficient container transfers
    

They are the backbone of modern C++ performance.

---

# 6️⃣ Relaxed `constexpr` (Advanced but Nice)

C++14 allows more complex logic inside `constexpr`.

For competitive programming:

- Rarely critical
    
- Mostly relevant for compile-time utilities
    

---

# 7️⃣ Improved Lambda Captures

C++14 allows initializing captures:

```cpp
int x = 10;

auto f = [y = x + 5]() {
    return y;
};
```

This was NOT allowed in C++11.

---

## 🎯 Why Useful?

Cleaner closures without external helper variables.

Mostly useful in:

- Functional-style utilities
    
- Advanced STL usage
    

---

# 8️⃣ `[[deprecated]]` Attribute

Marks functions as deprecated:

```cpp
[[deprecated]]
void old_func();
```

Not relevant for contests.

More useful in library design.

---

# 9️⃣ Heterogeneous Lookup (Advanced STL Improvement)

Allows searching maps without constructing full key.

Example conceptually:

```cpp
map<string, int> m;
m.find("hello");  // without constructing string explicitly
```

More of a library performance improvement than a daily CP feature.

---

# ⚠️ Important Warning

Some C++03 / C++11 code may break under C++14.

Example:

- `std::gets` removal
    
- Some deprecated features
    

Always test under the standard required by the judge.

---

# 🧠 Competitive Programmer’s Realistic View

## What Truly Matters in C++14 for CP?

### 🔥 Most Useful Additions

1. Digit separators (`'`)
    
2. Binary literals (`0b`)
    
3. Generic lambdas
    
4. Better lambda captures
    

Everything else is secondary for contest performance.

|Feature|C++11|C++14|
|---|---|---|
|Lambdas|Yes|Generic lambdas|
|Range-for|Yes|Same|
|Move semantics|Yes|Same|
|Binary literals|No|Yes|

# 🎯 Final Takeaway

For competitive programming:

- C++11 = Major upgrade
    
- C++14 = Refinement and convenience
    

C++14 does NOT radically change CP coding style.

It makes:

- Code cleaner
    
- Lambdas more powerful
    
- Numbers more readable
